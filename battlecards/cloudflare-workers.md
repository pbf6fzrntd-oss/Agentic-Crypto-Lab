## Summary

Cloudflare Workers is Cloudflare's general-purpose serverless compute platform (V8 isolates, not containers) — it is not an MCP-specific product, but Cloudflare has built substantial first-party MCP tooling on top of it: an `agents/model-context-protocol` documentation section with guides for building and deploying remote MCP servers over Streamable HTTP, an `McpAgent` class (built on Durable Objects) for stateful server implementations, a `@cloudflare/workers-oauth-provider` TypeScript library that implements OAuth 2.1 (with PKCE) so a Worker can act as an OAuth provider to MCP clients, and a Workers AI Playground that doubles as a remote MCP test client. This makes Workers a materially different competitor than the other cards in this set (Glama, Smithery, Fast.io, Monid, Manufact, PandaStack): it is not selling "MCP hosting" as a product, it is a general compute platform you'd build an MCP server *on*, using Cloudflare's own SDK/library building blocks, and you own and maintain that code.

## Pricing

Source: Cloudflare's own docs source file `workers/platform/pricing.mdx`, fetched directly from `raw.githubusercontent.com/cloudflare/cloudflare-docs` (production branch) on 2026-09-16 — this is Cloudflare's own pricing content, accessed via its GitHub-hosted source rather than the rendered developers.cloudflare.com page (which was blocked to direct fetch in this environment). Cross-checked against web-search snippets attributed to developers.cloudflare.com/workers/platform/pricing/, consistent as of 2026-09-16.

- **Free plan**: no charge. 100,000 requests per day, 10 milliseconds of CPU time per invocation.
- **Paid plan**: minimum charge of $5/month per account. Includes 10 million requests per month and 30 million CPU milliseconds per month. Overage: $0.30 per additional million requests, $0.02 per additional million CPU milliseconds. Max CPU time per invocation on Paid is 5 minutes (default 30 seconds); max 15 minutes for a Cron Trigger or Queue Consumer invocation.
- **No additional charge for data transfer (egress) or bandwidth** on the Paid plan, per the same source.
- **Durable Objects** (required by Cloudflare's `McpAgent` class for stateful MCP servers — see Features) have their own limits, layered on top of the above: Workers Free plan includes 100,000 Durable Object requests/day, 313,000 GB-seconds/day, and 5 GB total storage (source: web-search snippets attributing to developers.cloudflare.com/durable-objects/platform/pricing and a Cloudflare changelog post "Durable Objects on Workers Free plan," accessed 2026-09-16 — not independently confirmed via a raw-doc fetch, flagged as search-snippet-sourced). Workers Paid plan includes Durable Objects usage under the same $5/month minimum, with additional per-request/GB-s overage beyond the included amounts.
- These are Workers/Durable Objects platform prices generally, not an "MCP hosting" line item — Cloudflare does not price MCP serving separately from general compute/request/storage usage.

## Features

Source: Cloudflare's own docs source files fetched directly from `raw.githubusercontent.com/cloudflare/cloudflare-docs` on 2026-09-16 (`agents/model-context-protocol/index.mdx`, `agents/model-context-protocol/guides/test-remote-mcp-server.mdx`, `agents/model-context-protocol/guides/securing-mcp-server.mdx`), plus web-search snippets attributed to developers.cloudflare.com and blog.cloudflare.com where noted.

- **Official MCP documentation section** (`developers.cloudflare.com/agents/model-context-protocol/`) covering MCP concepts (hosts/clients/servers, described as "a USB-C port for AI connectivity"), a getting-started guide for building/deploying a remote MCP server, an API reference, transport docs, and auth guides.
- **Transport**: remote MCP connections run over **Streamable HTTP** with OAuth authorization; local/stdio transport is documented for same-machine use. Per web-search snippets attributed to blog.cloudflare.com ("Bringing streamable HTTP transport and Python language support to MCP servers") and a GitHub issue on `cloudflare/agents`, historical `/sse` URLs continue to work as aliases routed to the same Streamable HTTP handler rather than serving the deprecated separate SSE transport — **this detail is search-snippet-sourced, not confirmed via raw-doc fetch; re-verify directly before quoting to a prospect**.
- **`McpAgent` class**: Cloudflare's SDK class for building MCP servers on Workers, built on top of **Durable Objects** (for state). A GitHub issue (`cloudflare/agents#172`, accessed via search 2026-09-16) indicates `McpAgent` internally uses a WebSocket connection to its underlying Durable Object even for SSE-facing clients — an implementation detail worth knowing but not something Shredly needs to expose, since Shredly customers don't write this code themselves.
- **`@cloudflare/workers-oauth-provider`**: a TypeScript library, installed via npm, that implements the OAuth 2.1 provider side (with PKCE) so a Worker can act as an OAuth server to MCP clients while also acting as an OAuth client to an upstream identity provider. Per Cloudflare's own docs (`securing-mcp-server.mdx`, directly fetched 2026-09-16), it "handles token management, client registration, and access token validation," and does not store secrets — only hashes — letting the developer's code focus on the consent screen rather than building token/PKCE handling from scratch. This is a library the developer installs and wires into their own Worker code, not a managed/hosted auth layer Cloudflare runs for them.
- **Testing tooling**: per Cloudflare's own docs (`test-remote-mcp-server.mdx`, directly fetched 2026-09-16), a deployed remote MCP server can be tested via (1) the `@modelcontextprotocol/inspector` npm package (a local visual testing UI), (2) the **Workers AI Playground**, which accepts a server URL and connects to it as an MCP client so tools show up in a chat UI, and (3) Claude Desktop via the `mcp-remote` local proxy package, with Cursor and Windsurf also documented as supporting remote MCP connections via their own config files.
- **V8 isolates / no cold starts**: Workers run on V8 isolates rather than containers/VMs, widely reported (search snippets attributed to blog.cloudflare.com posts "Eliminating cold starts with Cloudflare Workers" and "Cloud Computing without Containers," plus third-party benchmarks) as achieving cold starts under ~5ms and running in 200+ cities worldwide — **this performance framing is Cloudflare's own marketing claim, corroborated by third-party benchmark blog posts but not independently verified by Shredly; present as a Cloudflare claim, not an audited fact**.
- **Cloudflare's own dogfooded MCP server** at `mcp.cloudflare.com`: exposes roughly 2,500 Cloudflare API endpoints through a two-tool "Code Mode" pattern (`search` + `execute`, where an agent writes JS to query an OpenAPI spec and call `cloudflare.request()`), per direct fetch of `github.com/cloudflare/mcp/blob/main/AGENTS.md` on 2026-09-16 — illustrative of Cloudflare's own MCP engineering, not a hosting product a customer buys.

## Where Shredly wins

- **No code to write.** Building an MCP server on Workers means writing and maintaining actual server code — defining tools/resources, wiring `McpAgent`, choosing Durable Objects for state, and integrating `@cloudflare/workers-oauth-provider` into your own codebase. Shredly's pitch is the opposite: point at an existing REST API, database, or webhook and get a working MCP endpoint and a key — no SDK to learn, no repo to stand up and maintain, per CLAUDE.md's differentiator "vs. hand-coding an MCP server."
- **No OAuth library to wire up yourself.** `workers-oauth-provider` is a real, well-documented library, but it is a library — the developer still installs it, integrates it into their Worker, builds the consent screen, and owns upgrading it. Shredly handles MCP auth as part of the hosted product; there's no separate auth library dependency for the customer to adopt, patch, or debug.
- **Purpose-built for converting an existing API/DB, not building a server from scratch.** Workers + its MCP tooling is a toolkit for building a new MCP server as a software project (choose a transport, choose state storage, write tool handlers). Shredly's ICP (an SMB AI-team lead who already has an API or database and wants it agent-usable, not a team that wants to build and operate a Workers codebase) is better served by "connect and go" than by a well-documented but still from-scratch build.
- **No infra to run or monitor.** Even on Workers' serverless model, the customer owns the deployment: choosing Durable Objects vs. stateless, monitoring CPU-time limits (10ms/invocation on Free, up to 5 min on Paid) against their own tool logic, and debugging their own OAuth flow. Shredly runs and monitors the MCP layer directly, consistent with CLAUDE.md's "vs. self-hosting" differentiator, which applies here even though Workers itself is "serverless."
- **Pricing model matches the buyer.** Workers/Durable Objects pricing is metered compute (requests + CPU-ms + GB-s, layered across two separate services with two separate free-tier limits) — reasoning about a real deployment means combining Workers request/CPU limits with Durable Objects request/GB-s limits. Shredly's three flat tiers (Free / $10 Shared / $50 Private, per CLAUDE.md) are simpler for a budget-conscious SMB buyer reasoning about total cost without a usage model to build first.

## Where they win / honest gaps

- **Raw compute and scale.** Workers is Cloudflare's production global edge compute platform running in 200+ cities — a fundamentally larger-scale, more battle-tested piece of infrastructure than any MCP-specific hosting product, Shredly included. A team with real engineering capacity that wants to build a custom, highly-tailored MCP server with full control over runtime behavior has more raw horsepower and flexibility available here.
- **No vendor lock-in to an MCP-hosting company.** The MCP server is just a Worker — ordinary, portable, exportable JavaScript/TypeScript code using open building blocks (`McpAgent`, `workers-oauth-provider` are both open-source on GitHub per the sources below). A team that outgrows Cloudflare's specific product, or wants to self-host the same code elsewhere, isn't tied to a proprietary hosting layer the way they would be with an MCP-hosting SaaS.
- **Huge existing Cloudflare user base.** Many companies already run DNS, CDN, WAF, or other Workers projects on Cloudflare — for them, adding an MCP server is "one more Worker" on infrastructure and billing they already have, with no new vendor relationship to set up. This is a real adoption-friction advantage Shredly can't match for a prospect already deep in the Cloudflare ecosystem.
- **Essentially free at low volume.** 100,000 requests/day and Durable Objects' free allotment cost nothing — a low-traffic or prototype MCP server can run indefinitely on Cloudflare's free tier, undercutting even Shredly's own free tier if the customer is willing to write and maintain the code themselves.
- **First-party, actively maintained MCP tooling** (dedicated docs section, official `McpAgent` class, official OAuth library, AI Playground as a built-in test client) is a genuine step above a truly generic PaaS like plain Vercel/Railway, where a developer would need to wire up MCP transport and auth entirely themselves. Cloudflare's docs and libraries meaningfully lower that gap versus the "general PaaS" framing in CLAUDE.md — it is the strongest version of that competitor, not the weakest.

## Facts

- Cloudflare Workers is a general-purpose serverless compute platform (V8 isolates, not containers); it is not sold as an MCP-specific hosting product.
- Cloudflare publishes an official MCP documentation section at developers.cloudflare.com/agents/model-context-protocol/ with guides for building and deploying remote MCP servers.
- Remote MCP servers on Cloudflare use the Streamable HTTP transport with OAuth authorization, per Cloudflare's own docs (`agents/model-context-protocol/index.mdx`, fetched 2026-09-16).
- Cloudflare provides an `McpAgent` SDK class, built on Durable Objects, for implementing MCP servers on Workers.
- Cloudflare provides `@cloudflare/workers-oauth-provider`, an open-source TypeScript library implementing OAuth 2.1 with PKCE, which a developer installs and integrates into their own Worker code to add MCP auth; per Cloudflare's own docs, it handles token management, client registration, and access token validation, and does not store secrets, only hashes.
- Cloudflare's Workers AI Playground can act as a remote MCP client for testing a deployed server, alongside the `@modelcontextprotocol/inspector` npm package and Claude Desktop via the `mcp-remote` local proxy; Cursor and Windsurf are also documented as supporting remote MCP connections. (Source: Cloudflare's own docs, `agents/model-context-protocol/guides/test-remote-mcp-server.mdx`, fetched 2026-09-16.)
- Workers Free plan: 100,000 requests/day, 10ms of CPU time per invocation, no charge. (Source: Cloudflare's own docs, `workers/platform/pricing.mdx`, fetched 2026-09-16.)
- Workers Paid plan: $5/month minimum, includes 10 million requests/month and 30 million CPU milliseconds/month; overage $0.30/additional million requests, $0.02/additional million CPU milliseconds; no additional egress/bandwidth charges. (Same source, fetched 2026-09-16.)
- Durable Objects (required for stateful `McpAgent` servers) carry separate limits layered on top of Workers limits: Free plan includes 100,000 Durable Object requests/day, 313,000 GB-seconds/day, 5 GB storage; Paid plan usage is included under the same $5/month minimum with its own overage rates (search-snippet-sourced from developers.cloudflare.com/durable-objects/platform/pricing and a Cloudflare changelog post, accessed 2026-09-16 — not independently confirmed via raw-doc fetch).
- Cloudflare Workers is not an MCP-hosting company; a customer building an MCP server on Workers writes and maintains the server code, chooses/wires the `McpAgent` class and `workers-oauth-provider` library themselves, and owns the deployment.
- Shredly's pricing is flat: Free (no card required), Shared $10/month, Private $50/month, with no metered request/CPU/GB-s billing model, per CLAUDE.md.
- Shredly converts an existing REST API, database, or webhook into a hosted MCP server with no server code to write; Cloudflare Workers is a platform on which a developer builds that server code themselves.
