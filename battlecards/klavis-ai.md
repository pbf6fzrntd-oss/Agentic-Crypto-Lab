# Battlecard: Klavis AI (klavis.ai)

**Last checked: 2026-09-16**
**Relationship to Shredly: adjacent/gateway player, not a direct head-to-head competitor.** Same treatment as the Monid card — see "Where they win / honest gaps" before using this in outbound or content. Do not frame Klavis as a straight alternative to Shredly.

## Summary

Klavis AI is an open-source MCP integration platform (Y Combinator X25 batch) whose flagship product is **Strata** — a single MCP server/endpoint that lets an AI agent progressively discover and call tools across many *other* MCP servers/SaaS integrations (Gmail, Slack, GitHub, Linear, Notion, etc.), with managed OAuth and multi-tenant auth built in, instead of connecting an agent to dozens of separate MCP servers directly ([Klavis-AI/klavis GitHub README, fetched via raw.githubusercontent.com](https://github.com/Klavis-AI/klavis), 2026-09-16; [Klavis-AI/klavis LLM.md, fetched via raw.githubusercontent.com](https://github.com/Klavis-AI/klavis/blob/main/LLM.md), 2026-09-16). The company's own materials frame this as solving "tool overload / context overload" — most MCP setups get unusable past ~40-50 tools in context, so Strata routes intent → category → action → execution instead of exposing every tool schema at once (per search-cache summaries of docs.klavis.ai, 2026-09-16; docs.klavis.ai itself was not directly loadable in this session — egress to that domain was blocked for the fetch tool).

Klavis ships three product lines per its own GitHub README (primary source, directly fetched): **Strata** (the tool-discovery/routing MCP server), **MCP Integrations** (100+ prebuilt, OAuth-backed MCP servers for third-party SaaS tools), and **MCP Sandbox** (described in search results as environments for training/evaluating AI agents — not independently verified beyond the klavis.ai homepage title snippet, 2026-09-16). The Strata MCP server itself is open source (Apache-2.0, confirmed via direct GitHub fetch) and self-hostable via `pipx install strata-mcp` or Docker; Klavis also offers a hosted/cloud version at klavis.ai plus Python/TypeScript SDKs and a REST API (`api.klavis.ai/v1/mcp-server/`) (GitHub README, direct fetch, 2026-09-16).

**Core model difference from Shredly:** Klavis's business is aggregating and routing access across *many existing third-party tools and SaaS APIs it doesn't own* (Gmail, Slack, GitHub, etc.) through one gateway endpoint — it's a gateway/router layer, closer in shape to Monid or Zapier MCP than to Shredly. Shredly's business is hosting an MCP server in front of *one customer's own* proprietary API, database, or internal tool. **No first-party Klavis feature was found — in the GitHub README, LLM.md, or any source reviewed — for taking a customer's own proprietary/private API and turning it into a hosted MCP server the way Shredly does.** Klavis's "MCP Integrations" are pre-built connectors *Klavis wrote* for well-known third-party SaaS products, not a generic pipeline for wrapping an arbitrary customer's own backend. This is confirmed absent from the primary sources checked (GitHub README, LLM.md) rather than merely unmentioned in marketing copy — treat it as a genuine gap, not an oversight in this research.

Founded by (per secondary sources only — direct fetch of ycombinator.com/companies/klavis-ai was blocked in this session) engineers with backgrounds including Google DeepMind/Gemini and Lyft; part of YC's X25 batch; reported ~$500K seed reported around June 2025 in press coverage. **These founder/funding details are secondary-sourced (search-engine synthesis of YC/press pages) and not independently confirmed via a direct primary-source read — re-verify before repeating in outbound or content.**

## Features

- Strata: a single MCP endpoint that aggregates and progressively discovers tools across multiple underlying MCP servers, rather than dumping every tool schema into an agent's context at once (GitHub README/LLM.md, direct fetch, 2026-09-16).
- 100+ prebuilt MCP integrations with OAuth handled by Klavis, covering CRM, Google Workspace, dev tools (GitHub, Linear), sales, search, Slack, Gmail, Notion, and similar SaaS tools (GitHub README, direct fetch, 2026-09-16). Note: other sources cite different counts for the same catalog — a YC-page search synthesis said "50+ production-ready MCP servers," and one earlier search synthesis (matching the scope-note framing this battlecard was requested against) cited "600+ tools/SaaS apps." None of 50+/100+/600+ was reconciled by a source all three could be checked against; **100+ is the figure most directly sourced (Klavis's own GitHub README, fetched directly)** — treat 50+ and 600+ as unconfirmed until checked against a live klavis.ai page.
- Multi-tenant auth and managed OAuth: Klavis handles OAuth flows and per-user/per-tenant credential management for the integrations in its catalog, so an app doesn't have to build OAuth handling itself for each third-party tool (search-cache summary of docs.klavis.ai, 2026-09-16; not independently verified via direct fetch).
- Access surface: MCP protocol endpoint, Python/TypeScript SDKs, and a REST API; also emits tool-call formats for OpenAI function calling, Anthropic tool use, and Google Gemini function declarations in addition to raw MCP (GitHub README/LLM.md, direct fetch, 2026-09-16).
- Open-source self-host option: the Strata MCP server and individual per-tool MCP server images (e.g., `ghcr.io/klavis-ai/github-mcp-server`) are published on GitHub under Apache-2.0 and can be pulled/run via Docker or installed via `pipx install strata-mcp` (GitHub README, direct fetch, 2026-09-16). The GitHub repo has ~5.8k stars as of this check (direct fetch, 2026-09-16).
- **No first-party feature found for onboarding a customer's own proprietary API/database as a new hosted MCP server.** The integrations catalog is Klavis-built connectors to specific named third-party products, not a generic "point us at your API/OpenAPI spec" pipeline. This was confirmed absent, not merely unmentioned, in both the README and LLM.md.

## Where Shredly wins

- **Hosting a customer's own proprietary API/database as an MCP server.** This is Shredly's entire product and, per the primary sources checked, is not something Klavis offers — Klavis's catalog is pre-built connectors to well-known third-party SaaS tools that Klavis itself wrote and maintains, not a generic mechanism for wrapping an arbitrary customer's own backend.
- **Ownership and control of the served data/API.** With Shredly, the customer's own backend is the source of truth and Shredly runs the MCP layer directly in front of it. With Klavis, the agent is calling Klavis-maintained connectors to third-party products the customer doesn't own or control the API surface of.
- **Simple, flat, published pricing.** Shredly's Free / $10 Shared / $50 Private tiers are clearly stated at shredly.io/pricing. Klavis's pricing could not be confirmed from a primary source in this session at all — an SMB buyer evaluating "what will this cost me" gets a clear answer from Shredly today and an unclear one from Klavis absent a direct pricing-page check.
- **Direct self-serve fit for the "I have an API, agents need it" use case.** An AI-team lead who already has their own API/database and just needs it reachable by agents solves that faster and more directly with Shredly than by adopting a many-tool aggregation/routing gateway aimed at a different problem (connecting to other companies' SaaS tools).

## Where they win / honest gaps

**Read this before using Klavis in a comparison — it addresses a genuinely different, adjacent problem well, and has real traction behind it.**

- Klavis solves "give my agent one connection to many existing third-party SaaS tools, with OAuth and multi-tenant auth handled for me" well — this is a real, differentiated use case Shredly does not address (Shredly hosts one customer's own API, not a catalog of other companies' tools).
- Real traction and credibility signals worth acknowledging honestly: YC X25-backed, open-source repo with ~5.8k GitHub stars (direct fetch, 2026-09-16), and reported (secondary-sourced, unverified via direct fetch) seed funding around $500K reported mid-2025.
- **Open-source self-host option is a genuine alternative** for a team that wants to run its own MCP gateway/aggregation layer rather than pay for a hosted one — Strata is Apache-2.0 licensed and can be self-hosted via `pipx` or Docker at no license cost (confirmed via direct GitHub fetch). This is a real substitute for teams solving Klavis's specific problem (many-tool aggregation) themselves, the same way self-hosting is a real alternative to Shredly for teams solving Shredly's problem (single-API MCP hosting) themselves.
- Breadth of pre-built, OAuth-handled integrations to well-known SaaS tools (Gmail, Slack, GitHub, Linear, Notion, etc.) is a real differentiator for "connect my agent to common existing tools" that Shredly does not build or maintain — Shredly's product is exposing the customer's own API, not maintaining connectors to third-party products.
- **Confirmed gap, stated plainly:** no first-party Klavis feature was found (checked: GitHub README, LLM.md) for converting a customer's own proprietary API into a new hosted MCP server, distinct from its tool-aggregation gateway. Klavis is adjacent to Shredly, not a direct substitute, for that use case — same treatment as the Monid battlecard.
- **Sales/content guidance:** do not position Klavis as a like-for-like alternative to Shredly. Use it only when a prospect is explicitly weighing "one gateway for many existing third-party tools, with OAuth handled" (Klavis's category, same shape as Monid/Zapier MCP) against "host my own proprietary API/database as its own MCP server" (Shredly's category) — and say so explicitly.

## Facts

- Klavis AI (klavis.ai) is an MCP integration/gateway platform; its flagship product, Strata, is a single MCP server that aggregates and progressively discovers tools across multiple other MCP servers/SaaS integrations.
