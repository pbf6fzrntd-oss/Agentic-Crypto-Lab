# Version 2 research cockpit

Canonical historical branch: `claude/tender-maxwell-jxsuo3`. Other application branches are separate projects. The original Phase 1, historical validation and Phase 2 journals, strategy/configuration, and reports remain frozen.

Python 3.11+, standard library only. Run `python -m research_v2.demo`, then open `.demo/cockpit/index.html`. This recreates a deterministic fictional replay; it does not fetch market data, call an LLM, or place an order. Use cohort filters to inspect the replay and the separately labeled frozen journal. Exported decisions and manifest record lineage and methodology. Rebuilding reproduces the same files. No synthetic output is appended to the real journal.

Methodology v2 is intentionally a new cohort: a fixed BTC/ETH snapshot basket demonstrates chronology and evidence governance, not the original twenty-asset strategy or an optimized portfolio. Fill eligibility starts strictly after decision formation. Demo runs use a declared fixed replay clock; SNAPSHOT_PAPER decisions use the process UTC wall clock and reject observations older than one day or in the future. A new decision waits for a later snapshot to credit the first eligible bar open. Five-bar holding policy and daily interval persist per decision. The 0.4 minimum confidence matches the frozen risk rule; it is not tuned to results. All benchmark legs and their normalized anchor are fixed; missing/misaligned/stale/nonfinite inputs fail visibly. Mature positions are reviewed before evaluating new exposure. SQLite reserves unique economic decisions under BEGIN IMMEDIATE, including the methodology, instrument, interval and cutoff. Identical replay snapshots are idempotent; conflicting same-time or out-of-order snapshots fail. Pending-fill approvals reserve exposure.

For operator-supplied paper snapshots: `python -m research_v2.demo --snapshot snapshot.json --database .local/paper-v2.sqlite --out .local/paper-cockpit`. Use evidence_class SNAPSHOT_PAPER, never DEMO_FIXED. Look at `research_v2.demo.snapshots()` for schema. Each thesis needs explicit source, cutoff, completion time, direction/confidence/reasoning; each market needs source, exact provider mapping, aligned positive daily opens and observed timestamp. Include every bar from the frozen benchmark anchor through the observed date. Snapshots are stored in the database with SHA256 IDs. Preserve the database on durable disk; stop writers for backup and verify restore. Demo and paper inputs cannot mix in one database.

Snapshot lineage is operator supplied, not provider-authenticated or independently verified. No live-thesis/provider bridge is implemented; the new path has no paid-call spending and no order code. The old forward runner retains its historical fill/budget limitations and must not be represented as v2 or used to substantiate v2 performance claims. Connecting live inputs requires a separate reviewed adapter with provider identity/freshness checks and budget reservation before billed calls. Legacy records lack full interval and decision-completion lineage, and can credit fills before run time; the cockpit flags those limitations without rewriting history.

Replay results are not performance evidence. Real-price historical rows with stub theses remain non-LLM validation; original live-thesis rows are separately labeled and do not prove repeatable edge. The simple per-decision return is not portfolio equity, and overlapping outcomes are not independent samples. Validate demand for research transparency/experiment governance before a paid product offer.

Run `python -m unittest tests.test_snapshot_v2 -v`. Acceptance covers next-fill chronology, complete benchmark, stale/future rejection, duplicate parallel snapshots and unchanged legacy evidence. Roll back code without discarding paper databases; method changes require a separate database and version. Open generated exports only after confirming their input provenance.
